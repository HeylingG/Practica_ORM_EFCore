Mapeo Objeto‑Relacional (ORM): operaciones CRUD con Entity Framework Core

De escribir SQL a mano a trabajar con objetos: cómo un ORM traduce clases de Visual Basic .NET en tablas de MariaDB, y cómo construir un mantenimiento completo de productos en Windows Forms.

Visual Studio 2026 .NET 10 Windows Forms Visual Basic .NET MariaDB EF Core + Pomelo

1 Introducción: el problema de los dos mundos

En las sesiones anteriores conectamos formularios a MariaDB con MySqlConnection, MySqlDataAdapter y DataTable. Funciona, pero obliga a pensar en dos idiomas a la vez.

Nuestro programa piensa en objetos: un Producto tiene un nombre, un precio y pertenece a una Categoria. La base de datos, en cambio, piensa en tablas, filas y columnas unidas por claves foráneas. Cada vez que guardamos o leemos datos tenemos que traducir manualmente de un mundo al otro: armar cadenas SQL, crear parámetros, leer columnas por nombre y convertir tipos.

A esa diferencia entre ambos modelos se le llama desajuste de impedancia objeto‑relacional (object‑relational impedance mismatch). Un ORM es la herramienta que hace esa traducción por nosotros.

2 ¿Qué es un ORM?

Un ORM (Object‑Relational Mapper, Mapeador Objeto‑Relacional) es una biblioteca que establece una correspondencia entre las clases de nuestro programa y las tablas de una base de datos relacional. Con esa correspondencia, el ORM:

↓Genera el SQL

Convierte consultas escritas en VB.NET (LINQ) en sentencias SELECT, INSERT, UPDATE y DELETE.

⇄Materializa objetos

Transforma cada fila devuelta por la base de datos en una instancia de una clase, con sus propiedades ya convertidas al tipo correcto.

◉Rastrea cambios

Recuerda qué objetos son nuevos, cuáles se modificaron y cuáles se eliminaron, y al guardar envía solo lo necesario.

ORM más comunes

PlataformaORMObservación

💡
Idea central. Un ORM no elimina el SQL: lo genera por nosotros. Saber SQL sigue siendo indispensable para entender qué hace el ORM y para diagnosticar problemas.

3 Conceptos fundamentales

EEntidad

Clase de VB.NET que representa una tabla. Cada instancia representa una fila. Ejemplo: la clase Producto.

CDbContext

Clase central del ORM. Representa una sesión de trabajo con la base de datos: abre la conexión, consulta, rastrea cambios y guarda.

SDbSet(Of T)

Propiedad del contexto que representa una tabla completa. Sobre ella se consulta, agrega o elimina: ctx.Productos.

MMapeo

Reglas que dicen qué clase va a qué tabla y qué propiedad va a qué columna. Se definen con atributos (<Table>, <Column>) o con la Fluent API.

QLINQ

Sintaxis de consultas integrada en VB.NET. EF Core la traduce a SQL: Where(Function(p) p.Precio > 100) se convierte en WHERE precio > 100.

TChange Tracker

“Rastreador de cambios”. Anota el estado de cada entidad (nueva, modificada, eliminada…) para saber qué SQL generar.

↺SaveChanges

Método que confirma el trabajo: revisa el rastreador y envía los INSERT/UPDATE/DELETE dentro de una transacción.

PProveedor

Paquete que adapta EF Core a un motor específico. Para MariaDB usamos Pomelo.EntityFrameworkCore.MySql.

NPropiedad de navegación

Propiedad que apunta a otra entidad, como Producto.Categoria. Representa en objetos lo que en tablas es una clave foránea.

Enfoques de trabajo

DBDatabase First

La base de datos ya existe y escribimos (o generamos) las clases que la representan. Es el enfoque que usaremos, porque ya sabemos crear tablas en MariaDB.

{}Code First

Se escriben primero las clases y EF Core crea las tablas mediante migraciones. Las herramientas de migración de EF Core generan código C#, por lo que en VB.NET resulta poco práctico.

8 Asincronía y concurrencia con el ORM

Una consulta a la base de datos puede tardar: la red, el servidor o el volumen de datos influyen. En Windows Forms, todo el código de los eventos corre en el hilo de la interfaz (hilo UI). Si ese hilo espera a MariaDB, el formulario se congela y Windows muestra “(No responde)”.

⚠️
Regla de oro. Un DbContext no admite dos operaciones al mismo tiempo. Si el usuario hace doble clic y se lanzan dos SaveChangesAsync sobre el mismo contexto, EF Core lanza “A second operation was started on this context instance…”. Por eso deshabilitamos botones mientras se espera y creamos un contexto nuevo por operación.

Concurrencia entre usuarios: control optimista

En una tienda real, dos cajeros pueden abrir el mismo producto a la vez. Si ambos lo modifican, el último en guardar sobrescribe al primero sin darse cuenta (pérdida de actualización). EF Core lo evita con un token de concurrencia: una columna (version_fila) que se incluye en el WHERE del UPDATE.

11 Errores comunes y cómo resolverlos

Unable to connect to any of the specified MySQL hosts

Causa: el servicio de MariaDB no está iniciado o el puerto es distinto de 3306.

Solución: en Servicios de Windows inicie MariaDB; verifique el puerto en HeidiSQL y corríjalo en ConexionBD.vb.

Access denied for user 'root'@'localhost'

Causa: contraseña incorrecta en la cadena de conexión.

Solución: ajuste Pwd= en ConexionBD.vb. Es el único lugar donde debe cambiarse.

Unknown column 'p.Id' in 'field list' (o similar)

Causa: falta el atributo <Column("…")> y EF Core usa el nombre de la propiedad como nombre de columna.

Solución: revise que cada propiedad tenga su <Column> con el nombre exacto de la tabla en MariaDB.

Table 'libreria_segovia.articulos' doesn't exist

Causa: sin <Table("…")>, EF Core usa el nombre del DbSet como nombre de tabla.

Solución: agregue <Table("productos")> sobre la clase o renombre el DbSet.

MissingMethodException o TypeLoadException al crear el contexto

Causa: se mezclaron versiones: Pomelo 9.0.0 con Microsoft.EntityFrameworkCore 10.x.

Solución: desinstale el paquete Microsoft.EntityFrameworkCore agregado manualmente y deje que Pomelo traiga su propia versión. Revise el .vbproj.

A second operation was started on this context instance before a previous operation completed

Causa: dos operaciones asíncronas usaron el mismo DbContext a la vez (por ejemplo, doble clic rápido o un contexto declarado como campo del formulario).

Solución: un Using ctx As New AppDbContext() por operación y deshabilitar botones mientras se espera (EstablecerOcupado).

The instance of entity type 'Producto' cannot be tracked because another instance with the same key value is already being tracked

Causa: el mismo contexto ya rastrea un objeto con ese Id y se intenta adjuntar (Attach/Update) otro objeto distinto con la misma clave.

Solución: usar contextos de vida corta y cargar la entidad con FindAsync antes de modificarla, como en la práctica.

Los cambios “no se guardan”, sin error

Causa: se olvidó SaveChangesAsync(), o se modificó un objeto obtenido con AsNoTracking() (el contexto no lo vigila).

Solución: para modificar, obtenga la entidad con seguimiento (FindAsync) y siempre termine con Await ctx.SaveChangesAsync().

Cannot add or update a child row: a foreign key constraint fails

Causa: CategoriaId vale 0 o un id inexistente (ComboBox sin selección).

Solución: valide cboCategoria.SelectedValue antes de guardar (función DatosValidos).

DbUpdateConcurrencyException

No es un error de programación: es el aviso esperado de que otro usuario cambió la fila. Se maneja informando al usuario y recargando los datos, como hace la práctica.
